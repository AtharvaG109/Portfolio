## Problem

LLM-powered apps are hard to assess consistently. Manual reviews catch prompt injection, role confusion, leakage, and citation failures, but the evidence is often scattered across notes, screenshots, and one-off prompts. I built LLM RedTeam Framework to turn those checks into a repeatable CLI workflow that stays safe for portfolio and CI use.

## Architecture

- Attack packs are YAML files with suites, tactics, probes, canaries, policy mappings, reproduction steps, severity, and CI gate weights.
- The runner supports single-turn and adaptive multi-turn sessions, including bounded mutations, confirmation probes, reproducibility probes, retries, and concurrency limits.
- Detectors combine exact synthetic canary hits, regex leakage checks, refusal classification, structured JSON detection, citation bypass detection, and false-positive suppression.
- Reports preserve redacted transcripts and evidence in Markdown, JSON, SARIF, JUnit, and SQLite history so findings can be replayed and compared.

## Security Constraints

- Built-in attacks use synthetic canaries and synthetic PII-shaped values only.
- Real target traffic only happens through explicit `redteam run` commands.
- API keys, bearer tokens, authorization headers, and common PII-shaped strings are redacted from transcripts and reports.
- Findings are reported as candidate evidence that requires validation, not proof of compromise or model intent.
- Tests use mocked endpoints or deterministic local lab adapters.

## Recruiter Demo

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
make release-check
redteam demo --profile vulnerable --output-dir reports/demo
redteam demo --profile hardened --output-dir reports/demo
```

The demo produces human and CI-friendly reports without a live LLM provider. The hardened profile blocks the enterprise smoke suite; the vulnerable profile emits synthetic canaries so the detector and report flow is visible.

## Tests And CI

- `make release-check` runs Ruff, strict mypy, pytest, package build, pack validation, and a hardened-lab demo.
- The current suite covers adapters, CLI commands, scoring, mutation generation, lab behavior, plugin discovery, report formats, redaction, and SQLite history.
- GitHub Actions runs the gate across Python 3.11, 3.12, and 3.13 and uploads built distribution artifacts.

## Deliberately Avoided

- No real PII packs or real secret extraction.
- No hidden network calls.
- No destructive target behavior.
- No web dashboard in this phase; the product is CLI plus serious evidence artifacts.
- No LangChain dependency in the default path, so request behavior remains transparent.
